# Архітектура AI-агента

## Проблеми, які розв'язує агент

Лабораторна робота автоматизує створення мінімального кросплатформного
застосунку Rust і його CI. Окремі операції мають бути повторюваними, не
пошкоджувати наявні файли та мати перевірювані критерії успіху. Фінальна
команда перевірки повинна бути лише для читання.

## Ролі та skills

Маніфест `.github/agents/build-engineer.agent.md` визначає роль Build Engineer,
межі відповідальності, правила роботи з файлами, заборонені дії та критерії
успіху.

| Skill | Відповідальність |
|---|---|
| `.github/skills/project-scaffold/SKILL.md` | Cargo-пакет `hello`, бінарник, бібліотечна функція `add` і тест `BasicAddition`. |
| `.github/skills/build-and-test/SKILL.md` | Скрипти `ci.sh` і `ci.bat`, які збирають пакет та запускають тести. |
| `.github/skills/github-actions/SKILL.md` | Одноджобовий workflow з матрицею Linux, Windows і macOS. |

Skills описують детальні контракти реалізації та перевірки. Агент застосовує
відповідний skill під час відповідної команди, а не генерує всі файли
безконтрольно.

## Команди

| Prompt | Призначення |
|---|---|
| `/git-init` | Ініціалізує Git лише за відсутності репозиторію; не створює коміт і не змінює гілки чи remotes. |
| `/create-project` | Створює або узгоджує мінімальний Rust-проєкт. |
| `/create-build` | Створює або узгоджує кросплатформні локальні CI-скрипти. |
| `/create-actions` | Створює або узгоджує GitHub Actions workflow. |
| `/check` | Перевіряє вимоги без змін у файлах репозиторію. |
| `/init-agent` | Оркеструє попередні п'ять команд у визначеному порядку та зупиняється на першій помилці. |

## Потік і дані між етапами

Порядок виконання: `/git-init` → `/create-project` → `/create-build` →
`/create-actions` → `/check`.

Етапи передають одне одному стан через файли репозиторію, а не через
тимчасовий формат даних:

1. Git-етап підтверджує корінь репозиторію.
2. Scaffold створює `Cargo.toml`, `Cargo.lock`, `src/main.rs` і `src/lib.rs`.
   Наступні етапи отримують назву пакета, Cargo-команди та контракт тесту з
   цих файлів.
3. Build-етап створює `ci.sh` і `ci.bat`; Actions-етап викликає їх, не
   дублюючи команди Cargo.
4. Check звіряє всі файли між собою та вимогами. Він не виправляє помилки.

## Обробка помилок та ідемпотентність

- Кожна команда має явні передумови, очікувані файли, перевірки й формат
  повідомлення про помилку.
- За відсутньої передумови або невдалої перевірки агент зупиняє поточний етап,
  називає команду/файл і наводить спостережену помилку.
- `/init-agent` не запускає наступний етап після помилки.
- Перед редагуванням агент читає наявні файли та зберігає сторонній вміст.
  Повторний запуск узгоджує потрібні ділянки замість повторного додавання
  секцій чи job.
- Жодна команда не видаляє файли, не виконує force-push і не змінює захист
  гілок чи секрети.
- `/check` не редагує та не генерує файлів. Якщо запускає Cargo-тести, збірка
  має бути спрямована в нову тимчасову директорію поза репозиторієм; стан
  репозиторію перевіряється до й після.

## Відповідність файлів ролям

| Шлях | Призначення |
|---|---|
| `.github/agents/build-engineer.agent.md` | Роль, відповідальність, правила й критерії завершення агента. |
| `.github/skills/*/SKILL.md` | Повторно використовувані інструкції для трьох технічних областей. |
| `.github/prompts/*.prompt.md` | Виконувані користувачем команди, їх послідовність і контракти. |
| `Cargo.toml`, `Cargo.lock`, `src/`, `.gitignore` | Згенерований Rust-проєкт; створюється `/create-project`, не під час написання цієї документації. |
| `ci.sh`, `ci.bat` | Локальна збірка й тестування; створюється `/create-build`. |
| `.github/workflows/ci.yml` | Автоматизація CI; створюється `/create-actions`. |
| `.gitignore` | Виключення `target/` і `build/`; створюється/узгоджується під час генерації проєкту. |
| `docs/architecture.md`, `docs/usage.md`, `docs/ai-log.md` | Архітектура, інструкція користувача й журнал роботи. |


## Відхилення від рекомендованої структури

Через вибір Rust (варіант 4) структура адаптована:

- `Cargo.toml` і `Cargo.lock` виконують роль `CMakeLists.txt`.
- Юніт-тест `BasicAddition` розташований у `src/lib.rs` (модуль `#[cfg(test)]`),
  тому окремого каталогу `tests/` немає; це стандартна практика для Cargo.
- Команда `/init-agent` відповідає orchestrator-команді `init` з методички.
- `ci.sh` і `ci.bat` викликаються з `.github/workflows/ci.yml`, який сам
  не містить команд збірки.
